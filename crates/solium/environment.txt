# Solium's command-line flags and environment variables.
#
# The source of the "Flags and environment" page of the documentation site,
# which dev/docs/generate.py builds from this file and adds, for each name,
# the places in the code that read it. The test
# `the_environment_reference_lists_exactly_what_the_code_reads`
# (crates/solium/src/script/reference.rs) fails when the compositor reads a
# `SOLIUM_*` variable or a `--flag` this file does not list, or this file lists
# one nothing reads. Only production code counts: a name used only in a test
# or a comment is not a knob, and does not go here.
#
# The format: a line starting with `#` is a comment, and one starting with
# `## ` begins a group. An entry is a name at the start of a line, optionally
# followed by what it takes, then its description on the lines below, indented
# by four spaces. Descriptions are Markdown, and a relative link in one is
# relative to this file.

## Flags

Every argument is checked before anything starts, and one Solium does not
know is refused with exit status 2. One of `--tty`, `--check`, `--check-qml`,
`--probe`, `--help` and `--version` chooses what Solium does, anywhere on the
line; with none it starts a compositor: nested, as a window, when
`WAYLAND_DISPLAY` or `DISPLAY` is set, and on the hardware otherwise.

--help
    Print how to run Solium, its flags and the variables that change a
    session, and exit. Also `-h`. Starts nothing.

--version
    Print the version, and the commit it was built from when it was built
    from a git checkout (`solium 0.0.0 (dfc95ce)`), and exit. Also `-V`.
    Starts nothing.

--tty
    Run on the hardware from a free virtual terminal, taking the screen, and
    write the session log, `$XDG_STATE_HOME/solium/session.log` (or
    `~/.local/state/solium/session.log`).

--session
    Only with `--tty`, anywhere on the line. `solium --tty --session` is
    the user's graphical session, and tells systemd and D-Bus so: it exports
    `WAYLAND_DISPLAY` and the rest, starts `solium-session.target`, and
    undoes both on exit. `solium-session`, which the session file starts,
    runs it this way. Without it, `--tty` tells nobody unless
    `SOLIUM_SESSION_BUS` names a bus.

--check
    Load the configuration, print every binding it registered and every one
    it removed, build every scene it declares at load and every pane style of
    your own, and exit; also the pane style and the loading scene this run's
    environment names, and every effect folder in `~/.config/solium/effects/`
    and every effect the configuration names, compiling their shaders on the
    first render node when there is one. Exits with 1 when anything fails:
    the configuration fails to load or sets a key nothing reads, a scene
    fails to build, misses a required property, or warns while it is built
    and first drawn, or an effect fails its Lua, its checks or its compile.
    Scenes are built in software, on one monitor. `--check <file.qml>` checks
    one QML file instead, as `--check-qml` does; `--check <dir>` checks one
    effect folder, and starts no Qt. Starts no compositor and needs no
    display.

--check-qml <file.qml>
    The old spelling of `--check <file.qml>`: load one QML file in software
    and, for a style's `Pane.qml`, every layer it names; print what went
    wrong; exit with 1 when anything did. A style that requires the GPU is
    said to, and its layers are not loaded. Starts no compositor.

--probe
    Print every connector and every mode it offers, without taking the
    screen. Safe to run inside another session.

--probe-qml-gpu
    Internal. The child process the QML GPU trial runs in; see
    [QML on the GPU](../../dev/README.md#qml-on-the-gpu).

--debug-mode
    Add the Developer Tweaks panel, on `super+shift+d`. Read anywhere on the
    command line.

--qml <mode>
    Which scene graph QML renders on: `auto`, `gpu` or `software`. Also
    written `--qml=<mode>`, and read anywhere on the command line. Wins over
    `SOLIUM_QML`, `SOLIUM_QML_GPU` and the configuration's `qml.renderer`.

## Running a session

SOLIUM_LUA_INIT=<path>
    Load this configuration instead of `~/.config/solium/init.lua` or the
    shipped `init.lua`.

SOLIUM_TERMINAL=<command line>
    The terminal `super+return` opens, split on spaces. Unset, the shipped
    `init.lua` opens the first terminal it finds installed.

SOLIUM_PANE=<name or path>
    The frame style for this run, over the configuration's `pane`.

SOLIUM_DECORATION=<name or path>
    The old spelling of `SOLIUM_PANE`. `SOLIUM_PANE` wins when both are set.

SOLIUM_QML_TITLEBAR=<path>
    One QML file to frame every window with, over `SOLIUM_PANE` and the
    configuration. The oldest spelling of the knob.

SOLIUM_LOADING=<name or path>
    The scene a window shows before its application arrives, over the
    configuration's `loading.scene`.

SOLIUM_QML_CURSOR=<path>
    The QML file the compositor's own pointer is drawn from, instead of the
    shipped `cursor.qml`. Used only when no XCursor theme is in force.

SOLIUM_QML_PATH=<paths>
    The whole QML import path, colon separated. Replaces the search rather
    than adding to it: the user's `~/.config/solium/qml` and the shipped QML
    are no longer looked in.

SOLIUM_QML=<mode>
    Which scene graph QML renders on: `auto`, `gpu` or `software`. Below
    `--qml`, above `SOLIUM_QML_GPU` and `qml.renderer`.

SOLIUM_QML_GPU
    The older spelling of `SOLIUM_QML=gpu`. Set to anything, it means `gpu`.

SOLIUM_FORM_FACTOR=<form factor>
    `desktop` (the default), `laptop`, `tablet` or `phone`. Chooses the input
    profile: click or touch to focus, whether focus follows the pointer,
    natural scrolling and the drag modifier. An unknown value is logged and
    `desktop` used.

SOLIUM_DRAG_MODIFIER=<modifier>
    `logo` (also `super` or `meta`) or `alt`: the key held to drag a window
    from anywhere in it. Over the form factor's default.

SOLIUM_DEBUG_MODE
    Set to anything, the same as `--debug-mode`.

SOLIUM_NO_DMABUF
    Set to anything, clients are not offered `linux-dmabuf` and fall back to
    shared memory.

SOLIUM_SESSION_BUS=<address>
    The D-Bus address to tell about the session, and to own
    `org.freedesktop.ScreenSaver` on (`idle.dbus_inhibit`), instead of the
    session bus. Nested, or `solium --tty` without `--session`, this is the
    only way either happens. Blank counts as unset. For checking the calls against a
    private bus: `dbus-run-session -- sh -c
    'SOLIUM_SESSION_BUS=$DBUS_SESSION_BUS_ADDRESS solium'`.

## Hosting a shell

A shell is loaded as configuration, with `shell = { scene = ... }`; see
[Where Solium ends and Lilium begins](../../docs/shell-boundary.md). These
change that for one run, and `dev/run-shell.sh` sets both.

SOLIUM_SHELL_SCENE=<file.qml>
    The QML file to host as the shell, over the configuration's
    `shell.scene`. Empty counts as unset.

SOLIUM_SHELL_WATCH=<directory>
    Where to look for changed `.qml` files, down to four directories below
    it, before rebuilding a hosted scene, instead of the scene's own
    directory. For a shell whose files live in a tree of their own.

## Development and testing

These exist so the compositor can be driven and photographed without a hand
on the keyboard. [dev/README.md](../../dev/README.md) says how they are used.
The ones marked **nested only** are read by the nested backend alone: on the
hardware, with `--tty`, they do nothing.

SOLIUM_CAPTURE=<path>
    **Nested only.** Write a rendered frame to `<path>` as a binary PPM.

SOLIUM_CAPTURE_AT=<ms>
    **Nested only.** Capture at this many milliseconds after startup, instead
    of once a window has settled.

SOLIUM_CAPTURE_FRAMES=<n>
    **Nested only.** Capture a burst of `n` frames rather than one, written
    beside the path `SOLIUM_CAPTURE` names with a number added to its stem:
    `/tmp/frame.ppm` gives `/tmp/frame-000.ppm`, `/tmp/frame-001.ppm`, ….

SOLIUM_CAPTURE_INTERVAL=<ms>
    **Nested only.** The time between the frames of a burst. 16 by default.

SOLIUM_TRIGGER_AT=<ms>:<combo>,...
    **Nested only.** Run what these key combinations are bound to, at these
    moments: `5200:super+space,6200:super+space`. The binding is looked up by
    the name written here, so this skips what a real key goes through first:
    the Ctrl+Alt chords, the lock screen and the key-cap lookup that keeps
    bindings working under another keyboard layout.

SOLIUM_KEY_AT=<ms>:<key>,...
    **Nested only.** Press a key and let it go at these moments, through the
    real input path: `1500:caps_lock,3000:shift+alt_l`. A key is keysym names
    joined by `+`, pressed in the order written and let go in reverse;
    `shift`, `ctrl`, `alt` and `super` are the left-hand keys. Each is found
    in the live keymap, in any of its layouts, so Caps Lock locks Caps, an
    xkb layout-switch option switches the layout, and a combination a binding
    claims runs it, exactly as from the keyboard.

SOLIUM_CLICK_AT=<ms>:<x>,<y>;...
    **Nested only.** Hand a press at these moments and places, separated by
    semicolons, to the mode that is holding the pointer, such as overview. It
    goes to the scripts, not through the input path: for a real press, use
    `SOLIUM_DRAG_AT` with the same point at both ends.

SOLIUM_DRAG_AT=<ms>:<x1>,<y1>><x2>,<y2>;...
    **Nested only.** Drag the pointer from one place to another, through the
    real input path, the real grab and the real layout scripts.

SOLIUM_LOADING_AT=<ms>:<program>,...
    **Nested only.** Open a window for an application that will never arrive,
    to exercise the loading window.

SOLIUM_OUTPUTS=<n>
    **Nested only.** Give the nested backend `n` monitors, from 1 to 4, side
    by side in its one window.

SOLIUM_OUTPUTS_AT=<ms>:<n>,...
    **Nested only.** Change the number of nested monitors at these moments:
    hotplug without a cable.

SOLIUM_MEMDIAG
    Set to anything, report what the compositor is holding, once a second.

SOLIUM_PACING
    Set to anything, say where a frame's time went on the frames that took
    longer than the monitor's frame interval, and say it too when a monitor
    flipped late, which is counted apart as `late`: the vblanks a monitor
    should have flipped at and did not, summed over the monitors, from the
    kernel's flips (always 0 nested, where there are none). On a monitor with
    vrr on, whose vblank waits for its frame, a slow frame drawn at a flip
    delays the next vblank instead of missing it and is rarely counted, while
    one started from idle is still judged against the monitor's fastest rate,
    so vrr's `late` does not compare with a fixed rate's. A line carries the
    slowest pass since the last line: each phase on the CPU, the three
    scenes Qt spent the most of it on, costliest first (`qml_top`, as
    `rounded/Frame=410`: each scene's folder and file, `@` the monitor it is
    hosted on if it is, and its microseconds), how many windows were
    captured (`captures`), and the GPU's time for the pass
    (`gpu`, `gpu_us`, and `gpu_prep_us` for the captures), which is read a
    few passes later, so a line waits up to eight passes for it and goes
    without it (`gpu="unread"`) after that, or sooner, still `gpu="unread"`,
    if nothing is being drawn and it has still not come (always nested,
    where the time is read only when a pass draws); `gpu` reads
    `unsupported` on a GPU that cannot time itself and `disjoint` when its
    clock jumped. `unread` is not `late`, which counts flips. Nested,
    only the captures and, with several monitors, each monitor are timed on
    the GPU, not the window's own draw. Each line also carries the GPU's
    clocks as that pass ended: where they come from (`clocks`: `nvml`,
    `i915` or `none`), `gpu_mhz`, `mem_mhz` (0 on i915) and NVIDIA's
    `pstate` (-1 where unknown), sampled four times a second by a thread of
    their own, and `none` until that thread has found them, which NVML can
    take a second or more to do; the log says what it found when it has.
    Misses and late flips are counted whether or not this is set, and every
    session ends with one `pacing` line of totals.

SOLIUM_FENCE_WAIT=<on|off>
    `off` (or `0`, `no`, `skip`) drops a window capture's fence instead of
    waiting for it on the CPU: the GPU orders the read after the draw on the
    one context. `on`, or unset, waits, which is the default until #59 lands.
    Each session's log says which it ran with.

SOLIUM_PACING_CLOCKS=off
    With `SOLIUM_PACING`, do not start the thread that samples the GPU's
    clocks (NVML, or i915's sysfs). For checking that sampling them does not
    itself keep the GPU out of its low-power states.

SOLIUM_TRACE=<path>
    Write one JSON line per pass (`drew` 0 for one in which no monitor was
    ready to draw), and one per page flip, to `<path>`, and turn
    `SOLIUM_PACING` on. Buffered and written once a second; put it on
    `$XDG_RUNTIME_DIR`. Not passed on to the programs Solium starts, so a
    Solium started inside a traced one does not write over its file.
    `dev/pacing-summary.py` reads it; the fields are in `dev/README.md`,
    under *Measuring frame pacing on a TTY*.

SOLIUM_RESIZE_TRACE=<file>
    Append a per-frame trace of every resize drag to `<file>`.

## Packaging

SOLIUM_DATADIR=<directory>
    Read when Solium is **built**, not when it runs: the first place the
    binary looks for its `qml` and `lua`. After it come the tree the binary was
    built in, then `../share/solium` beside the binary, then
    `/usr/share/solium`; the first that holds both is used.

## Also read

Not Solium's own, but they change what it does.

RUST_LOG=<filter>
    Log levels, in `tracing` filter syntax. `info` by default.

WAYLAND_DISPLAY
    With this or `DISPLAY` set and no backend flag given, Solium runs nested,
    as a window.

DISPLAY
    See `WAYLAND_DISPLAY`.

XDG_CONFIG_HOME
    Where `solium/init.lua`, `solium/user.lua` and `solium/qml` are looked
    for; `~/.config` when unset.

XDG_STATE_HOME
    Where the session log goes; `~/.local/state` when unset.

XCURSOR_THEME
    The pointer theme when the configuration's `cursor.theme` is not set.

XCURSOR_SIZE
    The pointer size when the configuration's `cursor.size` is not set.

XKB_CONFIG_ROOT
    Where xkb's data is; `/usr/share/X11/xkb` when unset. Solium reads
    `rules/evdev.xml` there for each layout's short name,
    `sol.keyboard().layout_short`. A layout the rules do not name, or every
    layout when the file is not there, gets the first two letters of its
    name, in capitals.
